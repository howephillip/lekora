# Artifacts (Phase 5)

Agents make web pages, documents, code and images that open in the app as their own thing, not a wall of text. Owner's choices (2026-11-15): artifacts may load anything online; edit them yourself **or** ask the agent to change them, every change a new version; a card in the chat plus each agent's Artifacts list; share as the file itself or as a PDF.

## What it is
- **Kinds:** web page (HTML, scripts and online libraries work), document (Markdown), code (with its language), image (SVG), plain text, **diagram** (Mermaid: flowcharts, sequences, timelines…, drawn by Mermaid) and **interactive component** (React: one JSX/TSX file with a default-exported component; hooks, Tailwind classes, other libraries by name from esm.sh) — the same kinds as Claude's artifacts. Up to 2 million characters per version.
- **Made by the agent with real tools** (AGENTS.md rule 7), offered only in Lekora chats, in Hermes' "lekora" toolset like `lekora_send_file`:
  - `lekora_create_artifact(title, kind, content, language?)`
  - `lekora_update_artifact(artifact_id, content, note?, title?)`: a new version; earlier ones are kept
  - `lekora_read_artifact(artifact_id, version?)`: the latest (with the user's own edits) or an earlier version
  - `lekora_list_artifacts()`
- **`lekora_edit_artifact(artifact_id, edits, note?)`** (owner, 2026-11-15: an agent changed two artifacts by editing Lekora's database with its own code, so no card appeared): line edits `{line_start, line_end, replacement}` and find/replace `{find, replace, all?}` on the latest version, a new version; the tool descriptions say artifacts are only changed with these tools. **Backstop:** every 5 s the plugin looks for artifacts with a newer version than their last card (changed any other way) and posts the card then, at the newest message.
- **Kept on the Hermes instance** (plugin store, `artifacts` and `artifact_versions`, every record with `instance_id` and `profile_id`), forever, like chats (rule 3). Deleting an agent puts its artifacts, every version, into that agent's backup (`<id>-<stamp>-lekora-chat.json`, `artifacts`).

## In the app
- **Card in the chat** for each artifact made or changed: title, kind, version ("Created", "Updated to v3"; your own edits show on your side as "You edited"). Tap to open full screen.
- **Code** (owner, 2026-11-15: code cards weren't coloured, and long lines looked uneven): syntax colours on the phone, offline (`CodeHighlighter`: comments, strings, numbers, keywords, types and functions for JavaScript/TypeScript, C/C++/C#/Java/Kotlin/Swift/Go/Rust/Dart/PHP, Python, Ruby, Bash/Shell, SQL, Lua, R; JSON and YAML keys; Dockerfile instructions; diffs in green and red; HTML/XML/SVG tags and attributes; any other language still gets comments, strings and numbers). Line numbers stay put while code scrolls sideways; text never enlarges unevenly; View menu: Wrap Long Lines, Larger/Smaller Text (remembered). Code blocks in documents that name their language are coloured too. **Edit Myself** on code, web pages and images opens a code editor: monospaced, coloured as you type, no autocorrect, smart quotes or capitals, and a row of coding keys above the keyboard (tab, brackets, quotes, operators); Cancel asks before throwing changes away. Language names read properly (JSON, TypeScript, SQL); a Dockerfile shares as `Dockerfile`, a diff as `.diff`.
- **Previews in cards** (owner, 2026-11-15, "as good as something like Claude code"): code, documents and text show their first lines, coloured (sent with the card); web pages, images, diagrams and components are drawn once on the phone, out of sight, waiting until a diagram or component has drawn, and kept as a small picture per version (diagrams and images shrunk to fit whole). The picture sits on top, trimmed to its area, above a solid title strip.
- **Also in the viewer:** ‹ v2 of 3 › arrows to step through versions; View › **Show Changes** (what changed since the version before: removed lines red, added green); Share › **Copy**; when a page, diagram or component hits an error, a banner with the error and **Ask <agent> to Fix** (sent as your message about the artifact). WebKit hides a page's error text from the page itself ("Script error."), so the app finds it by running a hidden copy of the page with each script wrapped to catch the error (a syntax error is found without running anything). Only text comes from the page; nothing goes back into it.
- **Not like Claude, on purpose or for now:** an artifact appears when the agent's tool call is finished (Hermes doesn't give the plugin a tool call's text while it's being written); no public share links (that needs a hosting service and an account: the owner's call, rule 9).
- **Viewer:** web pages and images in a sealed web view: scripts run and online content loads (owner's choice), but the page can't reach the app, your other data or other pages' storage. The only things that come across are its errors and what it keeps in localStorage. Documents are shown formatted (headings, lists, quotes, code, tables, links). Code in a monospaced, scrollable view with line numbers.
- **Versions:** the version menu shows each one (who made it, its note, when); open any; "Restore This Version" saves it as the newest.
- **Edit:** the text or code in an editor; Save makes a new version by you. If the agent changed it meanwhile, nothing is overwritten: you're told and the latest is loaded.
- **Ask to Change:** type what to change; it's sent to the agent as your message, with a chip showing which artifact. The agent gets the artifact's id with it, reads it and saves a new version.
- **Comments on lines** (owner, 2026-11-15: "select a line and add a comment … send all 6 comments to the agent at once", like Claude Code and Xcode): in code and text, and in a web page's, image's or document's source (View › Show Source), tap a line to select it, tap another for a range, then Comment. Each comment shows as a bubble under its lines (tap it to change or delete it); line numbers with comments are tinted. They're drafts, kept on this phone per Hermes instance and artifact until sent. **Review & Send** lists them all (tap to change, swipe to delete), with an optional note about the whole thing, and sends one message: a review card on your side of the chat; the agent receives every comment in line order with its line numbers and the lines it's about (quoted), and the artifact's id and version. Only our own line pages get the small bridge that reports taps (the artifact's text is escaped there); a web page running its own HTML never does.
- **Share:** the file itself (.html, .md, .svg, .txt, or code with its extension) or a PDF, through the share sheet.
- **Artifacts list:** the chat's "…" menu › Artifacts: everything this agent made, newest change first.

- **Cards remember their changes (owner, 2026-11-22):** what a page keeps in `localStorage` (ticked items, counts, inputs, settings) is saved on the Hermes instance shortly after each change and when the card closes, and put back when it next opens, on any phone and after a re-setup (rule 3). There is one copy per artifact, shared by all its versions, up to 1 MB. It's deleted with the agent. Comparisons and line views keep nothing. Agents are told (tool description, lekora-tools skill) to keep a page's state in `localStorage`. A page that only holds state in its scripts starts fresh each time.

## Files that are artifacts (owner, 2026-11-19)
- When an agent sends a file (`lekora_send_file`, or Hermes' own file sending) that an artifact can show, Lekora shows it as an artifact instead of a file: web pages (`.html`, `.htm`), documents (`.md`), diagrams (`.svg`, `.mmd`), code (by extension, with its language) and text (`.txt`), in UTF-8 and within the artifact size. The agent's caption is shown with the card. The tool tells the agent the new artifact's id, so later changes are new versions of it rather than more files.
- Anything else (PDFs, images, binary or oversized files) stays a file. A page that loads other files next to it (its own `.css`, images) shows without them: single-file pages work best.
